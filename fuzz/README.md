# Fuzzing

Coverage-guided fuzz targets for OpenTelemetry Python. Inputs are generated by
[Hypothesis](https://hypothesis.readthedocs.io/) strategies, and
[atheris](https://github.com/google/atheris) drives them through
[`fuzz_one_input`](https://hypothesis.readthedocs.io/en/latest/details.html#use-with-external-fuzzers).
The layout follows the conventions used by
[OSS-Fuzz](https://google.github.io/oss-fuzz/getting-started/new-project-guide/python-lang/).

## Running

On Linux, from the repository root:

```sh
uv run tox -e fuzz
```

This runs every target for a fixed number of iterations. Extra libFuzzer flags can be passed
through, e.g. `uv run tox -e fuzz -- -max_total_time=300`.

A target can also be run directly once `requirements.txt` is installed:

```sh
python fuzz/targets/fuzz_tracestate.py
```

### Reproducing a crash

libFuzzer writes a `crash-<sha1>` file containing the failing input. Pass it as the only argument
to replay it:

```sh
python fuzz/targets/fuzz_tracestate.py crash-<sha1>
```

## Adding a target

1. Add `targets/fuzz_<name>.py` with a Hypothesis `@given` test. Import the code under test inside
   `atheris.instrument_imports()`, and from `main()` pass the test's `.hypothesis.fuzz_one_input`
   to `atheris.Setup`, then call `atheris.Fuzz`.
2. If the input has a grammar, add it under `grammars/` with tests under `tests/`.
3. Add a command for the target to the `fuzz` environment in `tox.ini`.
4. Add any new dependencies to `requirements.in` and regenerate `requirements.txt`.
